# План улучшения инструментов фронтенда

Дата: 2026-10-04.

Стек уже современный: Vite, React 19 с React Compiler, TanStack Router и Query,
react-hook-form с zod, Tailwind v4, shadcn и oxlint. Менять фреймворки не нужно.
Больше всего даст небольшое число точечных вещей. План рассчитан на одного
разработчика и отсортирован по отдаче.

Связанный разбор ошибок: [FRONTEND_REVIEW.md](FRONTEND_REVIEW.md).

## 1. Генерировать API-клиент из OpenAPI — самая большая отдача

`backend/docs/openapi.yaml` теперь точно описывает бэкенд. Если генерировать из
него типы и запросы, пропадает целый класс ошибок, в том числе весь пункт 14
разбора фронта: `note: string` при `null`, `sizeBytes` строкой и обходы вида
`file.size_bytes`.

- **Инструмент:** orval с клиентом `react-query` (изначально в плане стоял
  `@hey-api/openapi-ts`). Он генерирует типы, функции запросов, хуки,
  `queryOptions` и хелперы инвалидации.
- **Попутно:** убрать самописное преобразование snake_case ↔ camelCase и
  работать с полями как в API. Это меньше магии и меньше рассинхрона.
- **Скрипт:** `bun run gen:api`. Изменил бэкенд — перегенерировал — TypeScript
  сам показал, что сломалось на фронте.

## 2. Включить строгий TypeScript

В `tsconfig.app.json` нет `"strict": true`, то есть строгая проверка выключена.
Поэтому `tsc` и проходит без ошибок. Стоит включить `strict` и
`noUncheckedIndexedAccess`. Сначала полезут ошибки, зато дальше TypeScript будет
ловить те `null`, на которых сейчас падает интерфейс.

## 3. Данные загружать в лоадерах роутера

TanStack Router и Query умеют работать вместе, а сейчас эта связка почти не
используется.

- В `loader` каждого маршрута вызывать `queryClient.ensureQueryData(...)`, плюс
  `pendingComponent` и `errorComponent` на маршрут. Тогда не нужны ручные
  `if (isLoading)` и бесконечные «Loading...», а ошибки показываются
  единообразно.
- Добавить глобальный обработчик ошибок в `QueryCache` и `MutationCache` (тост с
  текстом от сервера) и единое правило инвалидации после мутаций.
- Подключить `@tanstack/router-devtools` рядом с уже подключёнными devtools для
  Query.

## 4. Дизайн: перейти с ручных стилей на систему

Сейчас стили написаны вручную: `text-[13.5px]`, `#6366F1`,
`shadow-[0_1px_2px_...]`, и на каждой странице немного по-своему. Отсюда
ощущение «почти красиво».

- **Токены в Tailwind v4 через `@theme`.** Собственная шкала размеров текста
  (5–6 значений), цвета, радиусы и тени. Произвольные значения в квадратных
  скобках запретить себе как правило. Тёмная тема тогда достаётся почти
  бесплатно.
- **Полностью перейти на shadcn/ui.** `components.json` уже есть. Брать готовые
  Dialog, Select, Dropdown, Card, Tabs и Skeleton вместо самописных, а для
  страниц — блоки shadcn (настройки, дашборд, формы входа).
- **Тосты: `sonner` вместо `react-toastify`.** Визуально он сочетается с shadcn
  и даёт тосты с промисом.
- **Анимации: `motion`** (бывший framer-motion), точечно: появление списков,
  диалоги, кольцо прогресса. Не на всё подряд.
- **Даты:** `date-fns` уже есть. Сделать одну функцию форматирования с русской
  локалью вместо `toLocaleDateString("en-US")` в одних местах и `"ru-RU"` в
  других.
- **Язык:** выбрать один, скорее всего русский. Библиотеку i18n пока не тащить.

## 5. Тесты, но в меру

- **Vitest + Testing Library:** тестировать логику, а не вёрстку: `request.ts`
  (обновление токена), `formatDeadline`, схемы форм.
- **MSW:** моки API на основе того же OpenAPI. Фронт можно разрабатывать и
  показывать без поднятого бэкенда, а тесты используют те же моки.
- **Playwright:** 3–5 e2e-сценариев (регистрация, логин, создание предмета,
  создание задачи). Этого хватит, чтобы ловить баги вроде «личный предмет не
  создаётся».

## 6. Гигиена, которая экономит время

- **Один пакетный менеджер — bun.** `package-lock.json` удалить.
- **Скрипты:** `typecheck`, `test`, `gen:api`, `check` (линтер, форматирование,
  типы и тесты одной командой).
- **lefthook:** быстрые pre-commit хуки (oxlint, oxfmt, typecheck на изменённых
  файлах).
- **GitHub Actions:** на каждый push — `check` и `build`. Один файл.
- **Позже, когда будет прод:** Sentry на бесплатном тарифе, чтобы видеть ошибки
  пользователей.

## Чего не делать — избыточно для одного человека

- **Next.js и SSR:** приложение за логином, SEO не нужен, а SPA проще
  деплоить.
- **Redux, Zustand, Jotai:** серверное состояние покрывает React Query,
  локального хватает `useState`. Контекст для TOTP можно просто убрать.
- **Storybook:** много настройки ради компонентов, которые видишь сам.
- **Монорепозиторий, Nx, Turborepo, микрофронтенды, отдельный пакет
  дизайн-системы.**
- **Смена формы с react-hook-form на TanStack Form:** выгода не стоит
  переписывания.
- **Полноценный i18n-фреймворк**, пока не нужен второй язык.

## С чего начать

1. Bun как единственный менеджер, `strict` в TypeScript, скрипт `check`.
2. Генерация клиента из OpenAPI и перевод запросов на него.
3. Лоадеры маршрутов и глобальная обработка ошибок.
4. Токены дизайна и shadcn — по одной странице за раз, начиная с дашборда.
5. Vitest и MSW, потом несколько сценариев на Playwright и CI.

Первые три шага заодно закроют большую часть критичных пунктов из
`FRONTEND_REVIEW.md`.
