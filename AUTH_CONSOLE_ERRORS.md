# Проверка сессии в браузере

Обычная загрузка страницы гостем проверяет сессию через
`GET /api/auth/session`. Сервер возвращает `200` с
`{"authenticated": false}`, поэтому браузеру не нужно сначала получать
`401` от профиля и затем пробовать обновлять сессию.

- Действующий access-токен возвращает пользователя.
- Если access-токен истёк, сервер может обновить оба cookie по действующему
  refresh-токену и вернуть пользователя.
- Недействительные cookie очищаются, гость получает `200`.
- При одновременном обновлении в двух вкладках проверка может получить
  `409`. Фронтенд повторяет проверку с текущими cookie.
- Сетевые ошибки и ошибки сервера переходят в экран ошибки маршрута.

Защищённые запросы по-прежнему возвращают `401`, если сессия недействительна.
Ожидаемые ответы `401` записываются на уровне `Info`, остальные ошибки
клиента на `Warn`, ошибки сервера на `Error`.
